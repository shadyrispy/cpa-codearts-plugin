# v0.1.17

新增按账号设置会话并发上限，支持 Free 账号使用 3 路、具备相应权限的付费账号使用 5 路。

- 账号卡新增「会话并发上限」「保存并发上限」与当前本地占用；可设 1–64，0 表示继承全局默认。新增配置 `chat_session_concurrency`，默认 3。
- 设置写入独立的 `session-limit-*.state`，重启后保留，不修改凭证文件。降低上限不会中断已经运行的请求。
- 并发名额覆盖凭证准备、聊天、流式输出直至上游会话清理；完成、取消、失败或超时均释放名额。同账号在一个 CPA 进程内跨模型、跨客户端协议共用上限。
- 多账号调度优先选有空位的账号。选中账号满载时返回 409 和明确提示，不发送上游聊天请求、不无限排队，也不将本地占满误报成触发 CPA 额度冷却的上游 429。
- 新增并发竞争、设置持久化、页面保存、异常清理测试；真实 CPA + 模拟上游验证了 3/5 路上限、重启保留及释放后立即恢复调用。发布流程另执行 Linux race 测试与 Linux CPA 联调。

此功能不提升订阅本身的权限，也不自动识别套餐。计数只覆盖当前 CPA 进程；官方 VS Code 插件或其他 CPA 实例占用的上游并发不在本地计数中，请按实际使用预留名额。Docker 仍需持久化 `state_dir`。
