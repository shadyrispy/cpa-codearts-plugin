# v0.1.16

修复 v0.1.14/v0.1.15 每日活动领取接口错误，以及福利模型发现/注册不完整的问题。

- 福利模型首次发现自动执行，最多等待 5 秒；结果按账号持久化，重启、凭证轮换和调度开关变化不会清空目录。聊天不等待福利网关。页面「刷新并同步模型」会完整发现并请求 CPA 重新注册，无需手填模型列表。
- 每日活动改为官方 `ops/delivery → ops/claim → ops/confirm → delivery` 流程，仅处理 `USER_LOGIN` 的 `CREDIT` 活动。确认接口与官方活动状态均确认后才记成功；不自动领取注册、学生或邀请奖励。
- 领取幂等键与确认阶段持久化；确认失败时续办确认，不重复领取。旧 `daily-claim-*.state` 记录不再作为签到证据，新记录使用 `daily-welfare-*.state`，不会被旧的错误「已领取」挡住。
- 区分活动积分和福利模型 token 池，账号卡显示套餐/赠送积分的总额、已用和剩余（保留小数）。同时修正福利 token 余额查询的网关签名。
- 新增状态化领取/确认测试、持久模型目录及取消测试，真实 CPA 联调在没有配置福利模型列表时发现并调用福利模型。

原有任务开关与 `state_dir` 设置继续有效。数据库部署应保留独立持久目录。首次福利发现默认使用 CPA 代理，可用 `discovery_proxy_url` 单独覆盖。

验证说明：官方 26.9.102 插件代码与服务器只读接口确认了活动协议。测试账号当天已由官方客户端领取，官方状态为 `CONFIRMED`，因此未为测试重复发放或领取其他活动奖励。新领取与失败续办分支由真实 CPA + 状态化模拟上游测试覆盖。
